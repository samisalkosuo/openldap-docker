= OpenLDAP demo container
:toc: left
:toc-title: Table of Contents

OpenLDAP Docker container for demo purposes.

Based on https://catalog.redhat.com/software/containers/ubi9/ubi/615bcf606feffc5384e8452e[Red Hat UBI 9.8] with https://docs.fedoraproject.org/en-US/epel/[EPEL 9] providing `openldap-servers`.

== Use case

Occasionally I have a need to have LDAP server with groups and users. That's why this image exists. No installations, no setup, just run and use.

== Usage

* Get Docker image:
```
podman pull docker.io/kazhar/openldap-demo:latest
```
* Run Docker image: 
```
podman run -d -p 389:1389 -p 636:1636 --name openldap-demo docker.io/kazhar/openldap-demo:latest
```
* Login to server:
** Base DN: `dc=sirius,dc=com`
** Admin user: `cn=admin,dc=sirius,dc=com`
** Password: `passw0rd`

Or you can download/clone this repo and create and build your own OpenLDAP image.

=== Samples

* Add an ad-hoc group _staff_ and some users:
```
podman run -it --rm -p 1389:1389 -p 1636:1636 --name openldap -e LDAP_GROUP_STAFF="Ulysses Ser1, Uma Ser2, Uriel Ser3, Ulrich Ser4, Ursula Ser5, Upton Ser6, Uriah Ser7, Uliana Ser8, Ulma Ser9, Ulric Ser10" docker.io/kazhar/openldap-demo:latest
```

* Add your own organization, domain and create new self-signed certificates.

```
podman run -it --rm -p 1389:1389 -p 1636:1636 --name openldap -e LDAP_DOMAIN=wayne.net -e LDAP_ROOT="dc=wayne,dc=net" -e LDAP_ORGANIZATION="Wayne Machines" -e CREATE_CERTS=true docker.io/kazhar/openldap-demo:latest
```

* Add your own certificate
```
podman run -it --rm -p 1389:1389 -p 1636:1636 --name openldap -v /tmp_crt/ldap.crt:/certs/ldap.crt:z -v /tmp_crt/ldap.key:/certs/ldap.key:z -v /tmp/tmp_crt/ca.crt:/certs/ca.crt:z  docker.io/kazhar/openldap-demo:latest
```

* Run with persistence (data survives container restarts):
```
podman run -d -p 1389:1389 -p 1636:1636 --name openldap \
  -e LDAP_PERSIST=true \
  -v openldap-data:/var/lib/openldap/data:z \
  docker.io/kazhar/openldap-demo:latest
```

* Run with lightweight HTTP browser enabled (Web UI + curl):
```
podman run -d -p 1389:1389 -p 1636:1636 -p 8080:8080 \
  -e ENABLE_HTTP_SERVICE=true \
  --name openldap \
  docker.io/kazhar/openldap-demo:latest
```

== Groups and users

Groups and users can be configured via environment variables in two ways:

=== 1. Structured Groups and Users (`LDAP_GROUPS` and `LDAP_USERS_<GROUPNAME>`)

Specify a comma-separated list of groups in `LDAP_GROUPS`, and provide the users for each group in `LDAP_USERS_<GROUPNAME>` (case-insensitive group name).

For example:
```
LDAP_GROUPS="admin,research"
LDAP_USERS_ADMIN="Kiara Doyle,Zac Fraser,ashaw=newpwd,Arthur Port=newpwd"
LDAP_USERS_RESEARCH="Olivia Berry,Oscar Davis"
```

=== 2. Ad-hoc Groups and Users (`LDAP_GROUP_<GROUPNAME>`)

Quickly define or add a group and its users directly with an `LDAP_GROUP_<GROUPNAME>` variable without needing to list it in `LDAP_GROUPS`:

```
LDAP_GROUP_DEVELOPERS="John Doe,Jane Smith=secret,ashaw"
```

If a group is defined in both `LDAP_GROUPS` (with `LDAP_USERS_<GROUP>`) and `LDAP_GROUP_<GROUP>`, their user lists are combined.

=== User Format

Each user in a comma-separated user list can be specified in one of two formats:

1. **Full Name (`FirstName LastName[=password]`)**:
   - `givenName`: `FirstName`
   - `sn`: `LastName`
   - `cn`: `FirstName LastName`
   - `uid`: Derived from first letter of first name + lowercase last name (e.g. `Kiara Doyle` -> `kdoyle`)
   - `mail`: `<uid>@<LDAP_DOMAIN>` (e.g. `kdoyle@sirius.com`)
   - `password`: Custom password if `=password` is provided, otherwise `DEFAULT_USER_PASSWORD` (`passw0rd`).

2. **Arbitrary UID (`uid[=password]`)**:
   - `uid`: Lowercase UID (e.g. `ashaw` -> `ashaw`)
   - `givenName`: `User`
   - `sn`: Capitalized UID (e.g. `Ashaw`)
   - `cn`: `User <CapitalizedUid>` (e.g. `User Ashaw`)
   - `mail`: `<uid>@<LDAP_DOMAIN>` (e.g. `ashaw@sirius.com`)
   - `password`: Custom password if `=password` is provided, otherwise `DEFAULT_USER_PASSWORD`.

=== Backward Compatibility (Legacy Format)

The legacy format using `LDAP_USERS_AND_GROUPS` and `ADDITIONAL_LDAP_USERS_AND_GROUPS` is still supported:

```
LDAP_USERS_AND_GROUPS="admin:Kiara Doyle,Zac Fraser;research:Olivia Berry,Oscar Davis"
```

If either `LDAP_USERS_AND_GROUPS` or `ADDITIONAL_LDAP_USERS_AND_GROUPS` is set at runtime, legacy parsing is used and structured environment variables are ignored.

The default password for users when not specified is set by the `DEFAULT_USER_PASSWORD` environment variable.

== Create your own demo image

In order to create your own OpenLDAP image with custom domain and users, edit link:Dockerfile[Dockerfile] and then build a new OpenLDAP image.

* Edit link:Dockerfile[Dockerfile].
* Build image:
```
podman build -t my-openldap .
```
* Start:
```
podman run -it --rm -p 1389:1389 -p 1636:1636 --name my-openldap my-openldap
```

== Certificate

Certificate is created when image is built, using https://github.com/samisalkosuo/certificate-authority[My CA].

SANs in the certificate are:

```
DNS: openldap.<domain in LDAP_DOMAIN environment variable>
DNS: localhost
IP: 127.0.0.1
```

When starting the container, set `-e CREATE_CERTS=true` to create fresh self-signed certificates.

If you have existing certificates (for example, Let's Encrypt certs), add them as volumes when starting the container:

```
podman run -it --rm -p 1389:1389 -p 1636:1636 --name openldap-demo -v /my-certs/privkey1.pem:/certs/ldap.key:z -v /my-certs/cert1.pem:/certs/ldap.crt:z -v /my-certs/ca.crt:/certs/ca.crt:z docker.io/kazhar/openldap-demo:latest
```

* -v option maps file to file.

== Persistence

By default the container initialises a fresh database on every start. To retain data across container restarts:

. Mount a volume at `/var/lib/openldap/data`.
. Set `LDAP_PERSIST=true`.

When `LDAP_PERSIST=true` and the data directory already contains an existing database, the entrypoint skips re-initialisation and starts slapd directly against the existing data.

```
podman run -d -p 1389:1389 -p 1636:1636 --name openldap \
  -e LDAP_PERSIST=true \
  -v openldap-data:/var/lib/openldap/data:z \
  docker.io/kazhar/openldap-demo:latest
```

NOTE: On the very first run with a new empty volume, initialisation always runs regardless of `LDAP_PERSIST`.

== Lightweight LDAP Browser (Web UI & curl)

A lightweight, zero-dependency Python service (compatible with Python 3.9+) is embedded in the container for read-only directory browsing. It is disabled by default and can be enabled with `-e ENABLE_HTTP_SERVICE=true`.

=== Browser Access

Open your web browser and navigate to:

```
http://localhost:8080/
```

Key features:
* **Users view**: List of all users with search filtering, emails, and group memberships.
* **Groups view**: List of all groups and their assigned members.
* **Search**: Real-time search across UIDs, full names, emails, and group names.
* **Detail pages**: Click any user or group to view its full attributes and DN.

=== Terminal / curl Access

When accessed with `curl`, `wget`, or any plain-text client, the service automatically formats the directory entries into clean, readable terminal tables:

* Discover available endpoints and usage help:
```bash
curl http://localhost:8080/
# or
curl http://localhost:8080/help
```

* List all users:
```bash
curl http://localhost:8080/users
```

* List all groups and members:
```bash
curl http://localhost:8080/groups
```

* Search across the directory:
```bash
curl http://localhost:8080/search?q=doyle
```

* View specific user or group:
```bash
curl http://localhost:8080/user?uid=kdoyle
curl http://localhost:8080/group?cn=admin
```

* JSON API format:
Append `?format=json` (or set `Accept: application/json` header) to any endpoint:
```bash
curl -s http://localhost:8080/users?format=json
```

== LDAP CLI Tool & Scripts

All helper scripts and a unified Python CLI tool are included in the container image under `/scripts` (and symlinked to `/usr/local/bin/ldap-tool`), and can also be run directly from the host.

=== Unified Python CLI (`ldap-tool` / `scripts/ldap_tool.py`)

The unified CLI tool requires only Python 3.9+ standard library and standard OpenLDAP clients (`ldapsearch`, `ldapadd`, etc.).

==== Running Inside Container

```bash
# List all users
podman exec -it openldap ldap-tool list-users

# List all groups and member counts
podman exec -it openldap ldap-tool list-groups

# Search user by UID, name, or email
podman exec -it openldap ldap-tool search-user kdoyle

# Search group by name
podman exec -it openldap ldap-tool search-group admin

# Search anything
podman exec -it openldap ldap-tool search "Berry"

# Add a new user
podman exec -it openldap ldap-tool add-user "Alice" "Smith" "secret123" --group "research"

# Add an existing user to a group
podman exec -it openldap ldap-tool add-to-group asmith admin

# Delete an entry by DN
podman exec -it openldap ldap-tool delete-dn "uid=asmith,ou=users,dc=sirius,dc=com"

# JSON output for scripting: add --json
podman exec -it openldap ldap-tool list-users --json
```

==== Running on Host

On your host machine, ensure `scripts/variables.env` contains your connection parameters:

```bash
# List users
python3 scripts/ldap_tool.py list-users

# Search user
python3 scripts/ldap_tool.py search-user kdoyle

# Start standalone HTTP server on host
python3 scripts/ldap_tool.py serve --port 8080
```

=== Individual Shell Scripts

For simple one-off tasks, individual shell scripts are also available in `scripts/`:

* `search_by_user_id.sh <uid>`: Search user by UID
* `search_by_common_name.sh <cn>`: Search user by common name
* `search_by_last_name.sh <sn>`: Search user by surname
* `search_by_group_name.sh <group>`: Search group by CN
* `add_user.sh <first_name> <last_name> <password>`: Create a new user
* `add_user_to_group.sh <uid> <group>`: Add user to a group
* `delete_dn.sh <dn>`: Delete an LDAP DN

```
sh ocp-openldap-demo.sh uninstall <namespace>
```
